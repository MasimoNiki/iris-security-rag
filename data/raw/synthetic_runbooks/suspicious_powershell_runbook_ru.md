# Runbook: Анализ подозрительной PowerShell-активности

## Назначение

Документ описывает порядок первичного анализа подозрительной PowerShell-активности на Windows-хосте. PowerShell часто используется администраторами, но также может применяться злоумышленниками для загрузки вредоносного кода, обхода защитных механизмов, сбора данных и закрепления в системе.

## Когда использовать

Runbook используется, если SIEM, EDR или антивирус зафиксировали:

- запуск PowerShell с подозрительными параметрами;
- выполнение закодированной команды;
- загрузку данных из интернета;
- запуск PowerShell от имени необычного пользователя;
- выполнение PowerShell из офисного документа, браузера или архиватора;
- подозрительную активность после phishing-письма.

## Входные данные

Для анализа нужно собрать:

- имя хоста;
- имя пользователя;
- время запуска процесса;
- командную строку PowerShell;
- родительский процесс;
- дочерние процессы;
- сетевые соединения;
- загруженные файлы;
- события Windows;
- данные EDR;
- историю PowerShell, если доступна.

## Подозрительные параметры PowerShell

Особое внимание нужно обратить на параметры:

- `-EncodedCommand`;
- `-ExecutionPolicy Bypass`;
- `-NoProfile`;
- `-WindowStyle Hidden`;
- `-NonInteractive`;
- `IEX`;
- `Invoke-Expression`;
- `DownloadString`;
- `DownloadFile`;
- `FromBase64String`.

Сам по себе один параметр не всегда означает атаку, но комбинация нескольких признаков повышает риск.

## Анализ родительского процесса

Аналитик должен проверить, какой процесс запустил PowerShell.

Высокий риск, если родительский процесс:

- winword.exe;
- excel.exe;
- outlook.exe;
- chrome.exe;
- msedge.exe;
- firefox.exe;
- 7z.exe;
- winrar.exe;
- wscript.exe;
- cscript.exe.

Например, запуск PowerShell из Microsoft Word может указывать на вредоносный документ с макросом.

## Анализ сетевой активности

Нужно проверить:

- устанавливал ли PowerShell внешние соединения;
- к каким IP-адресам и доменам было обращение;
- использовались ли HTTP или HTTPS запросы;
- были ли скачаны исполняемые файлы или скрипты;
- есть ли домены с плохой репутацией;
- есть ли соединения с недавно зарегистрированными доменами.

Подозрительно, если PowerShell загружает скрипт из интернета и сразу выполняет его в памяти.

## Анализ командной строки

Командную строку нужно сохранить полностью. Если команда закодирована в Base64, её нужно декодировать в изолированной среде.

Признаки высокого риска:

- обфускация команд;
- длинная строка Base64;
- загрузка скрипта из внешнего URL;
- выполнение кода через `IEX`;
- отключение политик выполнения;
- попытки отключить защиту;
- запуск инструментов постэксплуатации.

## Возможные сценарии атаки

Подозрительная PowerShell-активность может быть связана с:

- phishing-вложением;
- загрузчиком malware;
- reverse shell;
- credential theft;
- lateral movement;
- reconnaissance;
- persistence;
- отключением защитных средств.

## Рекомендуемые действия

Аналитик может выполнить следующие действия:

- изолировать хост в EDR;
- сохранить командную строку и дерево процессов;
- проверить файл или скрипт, который был загружен;
- проверить сетевые индикаторы;
- проверить автозагрузку и scheduled tasks;
- проверить события входа пользователя;
- проверить соседние хосты на похожую активность;
- создать инцидент для IR-команды.

## Что логировать

В инциденте нужно сохранить:

- hostname;
- username;
- command line;
- parent process;
- child processes;
- external IP/domain;
- file hashes;
- decoded command;
- EDR alert ID;
- итоговую оценку риска.

## Итоговая классификация

Возможные статусы:

- benign admin activity;
- suspicious PowerShell;
- malware downloader;
- post-exploitation activity;
- confirmed compromise.
